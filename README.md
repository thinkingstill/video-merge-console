# 视频合并控制台

把任意目录下的零散视频，批量归一化成统一画幅后拼接成一个 MP4。提供 Web 控制台与纯命令行两种用法，零依赖、只依赖本机 FFmpeg。

支持递归子目录、按文件名自然排序、横竖屏方向自适应、多目录排队、单目录内并行编码。

## 功能

- **目录递归扫描**：任意层级子目录都会被遍历，隐藏目录与 `__MACOSX` 自动跳过
- **按文件名自然排序**：`clip_1 → clip_9 → clip_10`，不是字典序；同名文件按路径定序
- **方向自适应**：统计目录内横屏/竖屏占比，推荐画布（1080×1920 或 1920×1080），也可强制指定。判定会读取 `rotation` 元数据，正确处理手机竖拍素材
- **队列串行**：一次只跑一个目录任务，多目录入队后依次执行，互不争抢磁盘与 CPU
- **任务内并行**：单目录的归一化阶段按 worker 池并发，每实例限线程数，避免超订阅
- **实时进度**：SSE 推送，显示队列总览、当前分段、编码速度
- **可取消**：终止进程组并清理临时分段
- **画面不裁剪**：等比缩放后居中补黑边

## 环境要求

| 依赖 | 版本 | 说明 |
|---|---|---|
| Node.js | ≥ 18 | 服务端只用内置模块，无需 `npm install` |
| FFmpeg | ≥ 5.0 | 需要 `libx264` 与 `aac`；`scale` 的 `force_divisible_by` 需 4.4+ |
| 系统 | macOS | 在 macOS 上开发验证；`reveal` 按钮依赖 `open`，其他平台需替换 |

已验证组合：Node 22.22 / FFmpeg 8.0.1 / macOS（Apple Silicon）。

## 快速开始

### Web 控制台

```bash
git clone https://github.com/thinkingstill/video-merge-console.git
cd video-merge-console
node server.js
```

打开 http://127.0.0.1:8787，左侧点进目录 → 自动扫描并给出方向推荐 → 确认后加入队列。

可选环境变量：

```bash
PORT=8788 BROWSE_ROOT="$HOME/Movies" node server.js
```

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `8787` | 监听端口 |
| `BROWSE_ROOT` | `$HOME` | 目录浏览器可访问的根，超出范围会被拒绝 |
| `KEEP_TEMP` | 关 | 设为 `1` 时保留分段目录，便于排查 |
| `HOST` | `127.0.0.1` | 仅建议保持回环地址 |

### 命令行

```bash
chmod +x merge.sh

./merge.sh <输入目录> <输出文件.mp4>

# 例
./merge.sh ~/Movies/clips ~/Desktop/final.mp4
ORIENT=landscape ./merge.sh ~/Movies/clips ~/Desktop/final.mp4
```

| 变量 | 默认 | 说明 |
|---|---|---|
| `ORIENT` | `auto` | `auto` 按占比推荐 / `portrait` / `landscape` |
| `FPS` | `30` | 统一帧率 |
| `CRF` | `20` | 画质，越小越好、文件越大（18~23 常用） |
| `PRESET` | `medium` | `ultrafast` ~ `veryslow` |
| `KEEP_TEMP` | 关 | 保留中间分段 |

## 画面规则

| 输出方向 | 画布 | 横屏源 | 竖屏源 | 方形源 |
|---|---|---|---|---|
| 竖屏 9:16 | 1080×1920 | 缩到宽内，上下黑边 | 满屏 | 上下黑边 |
| 横屏 16:9 | 1920×1080 | 满屏 | 缩到高内，左右黑边 | 左右黑边 |

等比缩放后居中，不做任何裁剪。宽高比在 0.95~1.05 之间视为方形，不参与方向投票。

## 工作流程

```
扫描目录 → 判定方向 → 并行归一化（每段独立编码）→ 串行拼接 → 输出
```

两阶段是必要的：源视频的分辨率、帧率、编码器各异，直接拼接不可靠。先统一为 1080p 级别的 H.264/AAC 分段，再用 concat demuxer 复制流拼接——视频不二次编码，无画质损失。

拼接列表里为每段写入 `duration`（取视频流时长而非容器时长）。AAC 编码会让音频比视频长 10~20ms，若按容器时长累加，成品帧率会被误判为 60fps 且音画缓慢漂移。

## 输出位置

Web 控制台默认输出到**源目录的上一级**：

```
~/Movies/clips/          ← 源目录
~/Movies/clips_20261115_1830.mp4   ← 成品
```

不落在源目录内，是为了避免成品被下一次递归扫描当成素材重新并入。

## 性能参考

测试条件：Apple M4 10 核 / 16GB，8 段 1080×1920 30fps 10s 素材，`libx264 crf20`。

| 并发 | 每实例线程 | 总耗时 | 实际占用核数 |
|---|---|---|---|
| 1 | 自动 | 12.49s | 7.1 / 10 |
| 3 | 3 | 11.12s | 8.7 / 10 |
| 6 | 2 | 12.73s | 7.2 / 10 |

单实例已能吃满大部分有效算力，并行的加速比约 1.1x，超过 4 路反而回退。默认并发取 3。真正的提速手段是降 `preset`：

| 配置 | 单段均摊 | 相对 medium |
|---|---|---|
| medium crf20 | 1.56s | 1.00x |
| veryfast crf20 | 0.75s | 2.08x |
| h264_videotoolbox | 1.52s | 1.02x（滤镜链是瓶颈） |

## 已知限制

- 服务仅绑定回环地址，无鉴权，不要暴露到局域网或公网
- 扫描阶段每个视频一次 `ffprobe`，200 个文件约 1~3 秒
- 并发上限 6；更高并发在本机测试中收益为负
- 取消后临时目录会被清理，无法断点续跑
- 输出统一为 H.264/AAC MP4，暂不支持 HEVC 或无损输出
